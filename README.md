# LATTE ROOM ☕🫧

말없이 함께 쉬어가는 3D 무인카페. 기존 React 19 + TypeScript + Vite + React Three Fiber / Drei + Supabase 구조를 유지하며 확장한 버전입니다. 10개 독립 방, 동물 아바타 5종, 기존 12좌석 + 독서용 2좌석, 멀티플레이, 비눗방울이 포함됩니다. 모델과 소리는 코드로 직접 제작하며 외부 모델·음원 다운로드가 없습니다.

## 로컬 실행

Node.js 24 LTS 권장 (`.nvmrc` 제공, 최소 22.12).

```bash
npm install
cp .env.example .env.local
# 기존 Supabase 프로젝트 값을 .env.local에 입력
npm run dev
```

설정이 없으면 로컬 체험 모드로 카메라·이동·음료·디저트·비눗방울을 이용할 수 있습니다. 방명록은 가짜 로컬 저장을 하지 않으며 연결 설정 안내를 표시합니다.

| 변수                            | 설명                                                                  |
| ------------------------------- | --------------------------------------------------------------------- |
| `VITE_SUPABASE_URL`             | 기존 Supabase 프로젝트의 HTTPS URL                                    |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | publishable key 또는 레거시 anon key                                  |
| `VITE_TURNSTILE_SITE_KEY`       | **선택 사항:** 익명 인증 CAPTCHA용 Cloudflare Turnstile 공개 site key |

Vite 변수는 브라우저에 공개됩니다. `service_role`, secret key, Turnstile secret은 넣지 마세요. `.env.local`은 Git에서 제외됩니다. 변수 변경 후 개발 서버 재시작 / 배포 재빌드가 필요합니다.

## 조작과 기능

- 입장: 고양이·토끼·곰·강아지·수달, 닉네임 최대 16자. 방 선택에서 10개 공간을 이동합니다. 방당 고정 인원 제한은 없습니다.
- 이동: 바닥 클릭/탭으로 작은 원까지 자동 산책합니다. WASD / 방향키와 모바일 조이스틱도 유지합니다. 수동 입력은 자동 경로를 취소합니다. 의자를 클릭한 뒤 `앉기`를 누르면 가까이 걸어가 자리를 승인받고 앉습니다.
- 카메라: 기본은 항상 **낮은 3인칭 추적 시점**입니다. 캐릭터의 이동량을 카메라에 매 프레임 함께 반영하고 실제 캐릭터 위치를 바라보므로, 캐릭터는 화면 중앙 근처에 남고 카페 배경이 함께 스크롤됩니다. 회전·거리 변화에는 부드러운 보간과 충돌 처리를 적용합니다. 예전에 저장된 `latte:camera-mode=first`도 입장 시 `third`로 정리합니다. 1인칭은 전환 버튼으로 현재 세션에서만 선택할 수 있으며 새로고침 후에는 3인칭으로 시작합니다.
- 둘러보기: PC 마우스 드래그 / 모바일 화면 드래그. 3인칭 수직 각도는 -0.75~0.45 rad로 제한하여 과도한 탑뷰를 막습니다. 선택형 1인칭은 ±1.35 rad 범위입니다. 1인칭 WASD/방향키/조이스틱은 현재 바라보는 수평 방향 기준 전진·후진·옆걸음, 3인칭은 기존 월드 방향 이동입니다. 자동 산책은 두 시점 모두 위치를 추적하며 1인칭 시선은 경로 방향으로 천천히 돌아갑니다. 카메라 드래그가 새로운 이동 목적지를 만들지 않으며 조이스틱은 캔버스와 별도 포인터 영역입니다.
- 3인칭: 기본 거리 2.6, 위를 내려다보는 높은 고정 시점 대신 눈높이보다 조금 높은 뒤쪽 시점입니다. 휠/두 손가락 핀치로 0.8~8 거리 조절, 드래그로 자유 회전합니다. 시선은 실제 캐릭터를 향하며, 캐릭터 회전과 카메라 yaw를 분리해 옆걸음·방향 전환 때 시점이 갑자기 뒤집히지 않습니다. `시점 초기화`는 **현재 시점**에서 캐릭터가 보는 방향/기본 거리로 복귀합니다.
- 카메라 안전: 캐릭터의 눈 기준점에서 카메라까지 확장 AABB 충돌 검사를 하여 벽·가구 앞에서 거리를 줄입니다. 보간된 최종 위치도 재검사하고 바닥 높이 0.32 이상으로 제한합니다. near plane 0.04, 위치·회전 보간, 이동→아바타→카메라 순서의 프레임 처리를 적용합니다. 모델 충돌은 정밀 삼각형 대신 공유 가구 경계 상자를 사용합니다.
- 커피머신: 크림 베이지·실버의 독자적인 에스프레소 머신입니다. 원두 호퍼·압력 게이지·추출구·스팀 노즐·드립 트레이가 있습니다. 실제 브랜드 로고를 쓰지 않습니다. 클릭 또는 ☕ 도구로 메뉴를 열고 **메뉴 선택 → 추출하기**를 누릅니다. 블랙 커피는 약 4.5초, 우유 음료는 약 5.8초의 단계별 추출 후 앞발에 컵이 생깁니다.
- 음료: 에스프레소, 아메리카노, 라떼, 카푸치노, 바닐라라떼 + 기존 초코라떼. 데미타스·넓은 컵·키 큰 컵과 색·띠 장식이 구분됩니다. `마시기`로 컵을 입으로 가져가며 내용물이 줄어듭니다. 4번 마신 후 빈 컵을 정리할 수 있습니다.
- 디저트: 따뜻한 조명의 유리 쇼케이스에 크루아상·마카롱·쿠키·딸기 케이크·치즈케이크를 진열합니다. 기존 컵케이크·랜덤 선택도 유지합니다. 원하는 메뉴를 접시에 받고 `먹기`를 누르면 한입씩 작아지며 3회 후 접시를 정리합니다.
- 테이블: 카페 테이블 좌석에 앉았을 때 컵·접시를 내려놓거나 다시 들 수 있습니다. 먹고 마실 때는 손으로 가져갔다가 다시 놓습니다. 일어나거나 방을 옮기면 소지품을 손으로 회수합니다.
- 비눗방울: 🫧 탭으로 5~8개, 650ms 길게 눌러 대왕 방울 1개. Enter/Space, Shift+Enter/Space도 지원합니다. 약 7% 확률의 특별 무지개 방울, 반짝이·pop 효과음, 10.5초 수명, 1.8초 쿨다운, 방당 50개 상한을 적용합니다.
- 사운드: 상단 ON/OFF 또는 설정의 전체 음소거. 음악+실내 분위기 / 효과음 볼륨을 따로 조절하고 `latte:audio`에 저장합니다. 재방문 시 설정은 복원하지만 **사용자가 켜기 전에는 AudioContext를 만들거나 소리를 재생하지 않습니다**. 커피 추출, 도자기 컵, 마시기, 먹기, pop, 발걸음, 실내 공기·잔잔한 멜로디는 모두 Web Audio 자체 합성입니다. 음소거와 효과음 볼륨은 모든 동작에 적용됩니다.

## 4차 업데이트: 산책 · 독서 · 함께 키우는 정원

### 가벼운 경로 탐색과 인테리어

`world.ts`에서 실제 가구 위치와 충돌 영역을 함께 정의합니다. 테이블·14개 의자·책장·화분·머신·쇼케이스를 피하는 0.2 간격, 55×48 크기의 A* 격자를 방별로 캐시합니다. 대각선 모서리 통과를 막고 **정확한 선분/AABB 검사**로 경로를 단순화합니다. 막힌 목적지는 가까운 걸을 수 있는 곳으로 보정하고, 연결되지 않은 영역이면 도달 가능한 구역의 가장 가까운 지점을 선택합니다. 매 프레임 경로를 계산하거나 경로 자체를 전송하지 않습니다. 기존 최대 5Hz 위치/방향 메시지와 로컬 걷기 보간을 사용합니다.

PC 바닥 클릭과 모바일 탭은 R3F Raycaster의 실제 바닥 교점을 사용합니다. 새 목적지는 기존 경로를 교체하고 수동 이동은 경로를 취소합니다. 책·화분·의자 클릭은 이벤트 전파를 멈춰 뒤쪽 바닥 이동을 만들지 않습니다. 카메라 조작 중에는 기존 자동 산책도 잠시 멈춥니다.

10개 방은 기존 구조를 유지하며 파스텔 벽 색·책 표지 배치·책장 위치·화분 배치가 조금씩 다릅니다. 나무 책장, 잡지, 펼친 책, 독서 의자 두 개, 스탠드·사이드 테이블·러그·쿠션, 시계·액자, 원두 유리병, 컵/접시 선반과 창가 소품을 추가했습니다. 기존 방명록·머신·쇼케이스는 유지합니다. 반복 꽃잎/물방울은 공유 저폴리곤 지오메트리를 사용하고 추가 실시간 그림자/고비용 조명은 만들지 않습니다.

### 독서와 상황별 조작

책장에 있는 색깔 책을 클릭하거나 가까운 `책 열기` 안내를 누르면 제목과 짧은 문장을 읽을 수 있습니다. 문장은 이 프로젝트를 위해 직접 작성했으며 출판된 문장을 인용하지 않습니다. 문장을 고른 뒤 `독서 의자로` 또는 의자 → `앉기`로 걸어가 앉으면 앞발에 펼친 책이 나타납니다. 책 펼침/페이지·고개·눈 깜빡임을 가볍게 애니메이션하고, `책 덮기`/`일어나기`로 종료합니다. 커피나 디저트를 먹는 동작은 독서를 중단하고 진행합니다. 페이지·물소리는 기존 효과음/음소거 버스를 사용합니다.

책·의자·화분 근처에서는 상황별 안내만 표시합니다. 멀리 있는 의자/화분을 고른 경우 버튼을 누르면 가까이 걸어간 다음 동작합니다. 독서용 의자를 포함한 **14개 좌석**은 공유 좌석 승인과 임대로 관리합니다.

### 반복형 꽃 성장: 새 테이블 없이 Realtime으로

6개 화분마다 **씨앗(0) → 새싹(1) → 줄기(2) → 꽃봉오리(3) → 개화(4)**를 공유합니다. `물주기`를 누르면 접근한 뒤 물뿌리개·물방울·효과음이 나타나며 한 단계 자랍니다. 화분별 3.5초 쿨다운이 있고, 동시에 같은 이전 단계를 보고 누른 요청은 하나만 승인합니다. 개화 후 180초 유지하며 마지막 5초 동안 작아졌다가 씨앗으로 돌아옵니다. 매 주기의 꽃 모양과 색은 공유 seed로 정하고 다음 주기에서 다시 랜덤 선택합니다. 횟수는 **현재 주기 단계**이며 영구 수집/개인별 기록은 만들지 않습니다.

이 기능의 상태는 **Supabase Realtime Broadcast와 방 참가자 메모리**로 관리하며 Supabase DB에 영구 저장하지 않습니다. 기존 방명록/카페 테이블은 변경하지 않고, 추가 SQL·환경변수도 없습니다. 모든 참가자가 나가면 상태가 초기화될 수 있습니다.

- `roomState.ts`의 대표 클라이언트는 Presence에 연결된 v4 참가자 UUID를 정렬해 정합니다. 새 membership term마다 모든 참여자의 스냅샷을 모아 최신 revision을 복원한 후 쓰기를 허용합니다. 상대가 응답하지 않으면 불일치 상태에서 독자적으로 쓰지 않고 동기화를 기다립니다.
- 물주기는 고유 요청 ID와 화분별 단조 증가 version으로 중복/역순을 거절합니다. 쿨다운과 성장 단계는 대표가 검사하며 승인된 전체 상태를 배포합니다. 재접속/늦은 입장/대표 퇴장 시 상태를 다시 교환하며, 대표는 10초 주기의 체크포인트로 유실된 갱신도 복구합니다. 일반적인 연결 상태에서의 동시 요청과 리더 교체를 테스트합니다.
- 의자도 같은 승인 경로를 사용합니다. 좌석은 20초 임대, 앉은 방문자가 5초마다 갱신합니다. 퇴장·기한 만료 시 반환하고 오래된 release token으로 새 점유를 해제할 수 없습니다. 승인 전에는 앉지 않습니다.
- 연결 오류 동안 쓰기를 멈춥니다. 일시적인 네트워크 분할·유실의 복구는 Presence 재동기화에 의존하며 **DB 트랜잭션 수준의 전역 원자성이나 악의적인 공개 채널 위조 방지를 보장하는 구조는 아닙니다**. 그런 보장이 필요한 운영 환경에서는 서버 측 중재가 추가로 필요합니다. 장치의 자동 날짜/시간을 사용하는 것을 권장합니다.
- 새 버전 배포 후 모든 브라우저를 새로고침하세요. 예전 버전은 v4 정원/좌석 합의에 참여하지 않으며, 같은 기능의 일관된 사용에는 참가자 모두 v4가 필요합니다. 기존 방문자 수·아바타·컵·방울 프로토콜은 계속 유지합니다.

## 3차 업데이트: 추출 ASMR · 앞발 컵 · 랜덤 이름 · 걷기

- 첫 방문 시 형용사와 동물을 조합한 한국어 닉네임을 자동 생성하고 `latte:name`에 저장합니다. 기존 사용자 이름도 보존합니다. 입장 화면과 방 안의 `닉네임 변경` 버튼은 직전 이름과 다른 새 랜덤 이름을 만들고, 접속 중인 다른 방문자에게 갱신합니다. 방명록의 기본 이름도 이 이름입니다. 동명이인은 허용하며 UUID / Supabase Auth와 이름을 섞어 사용하지 않습니다.
- 컵은 아바타의 `앞발 → 컵` 3D 계층에 직접 부착합니다. 팔이 앞발을 향하고 손목이 회전을 보정하여 걸을 때 컵이 안정적으로 유지됩니다. 마실 때 앞발과 컵을 입으로 올리고 컵을 기울인 후 내려놓습니다. 컵을 든 팔과 먹는 팔은 걷기 흔들림보다 우선합니다. 마시고 먹는 동안은 이동을 잠시 멈춥니다.
- 로컬 및 원격 아바타의 실제 위치 변화량에서 보행 강도를 계산합니다. 앞발/뒷발이 교대로 움직이고 몸이 가볍게 오르내리며, 정지 시 보간으로 돌아옵니다. 대기 시 호흡과 눈 깜빡임을 추가했습니다. 기존 강아지를 유지하며 수달 모델도 추가했습니다.
- 모션은 각 클라이언트에서 계산하며 포즈 프레임을 전송하지 않습니다. 기존 최대 5Hz 상태 메시지에 선택 필드 `brewDrink`만 추가했습니다. DB 테이블 변경은 없습니다.

추출 소리와 모델은 `brewing.ts`의 하나의 시간표를 공유합니다:

| 단계        | 시간                            | 연출                                               |
| ----------- | ------------------------------- | -------------------------------------------------- |
| 분쇄        | 0~1.2초                         | 맥동하는 분쇄 잡음, 원두 진동                      |
| 펌프        | 1.2~1.9초                       | 저주파 모터/펌프, 압력 바늘                        |
| 추출        | 1.9~4.1초                       | 물줄기·방울 합성음, 추출구 흐름과 컵의 점진적 채움 |
| 우유 스티밍 | 4.1~5.4초, 우유 음료만          | 필터 잡음·스팀, 노즐 김                            |
| 완성        | 블랙 4.1~4.5초 / 우유 5.4~5.8초 | 짧은 완성 알림 후 앞발에 컵 제공                   |

공용 머신은 가장 최근 진행 중인 주문의 연출을 표시하고, 각 방문자의 컵 완성은 독립적으로 처리합니다.

모든 ASMR은 자체 Web Audio 합성이며 기존 효과음 버스를 통해 볼륨/전체 음소거가 적용됩니다. **현재 사용자가 추출 버튼을 누른 경우에만** 실행하고 다른 방문자의 주문 소리는 자동 재생하지 않습니다. 음소거 상태에서는 추출 음원을 만들지 않습니다. 단일 취소 가능한 재생 작업으로 관리하여 새 주문·방 이동·음소거·탭 숨김·컴포넌트 종료 시 예약된 다음 단계까지 중단하고, 정상 완료 시 노드를 정리합니다. 숨긴 탭에서 주문은 완료될 수 있지만 돌아왔을 때 지난 추출 소리를 재생하지 않습니다.

추가 환경변수와 새 SQL은 필요 없습니다. 기존 방명록 migration을 이미 적용했다면 다시 실행하지 마세요. 기존 Supabase/Turnstile 설정은 그대로 사용합니다.

개발 모드에서만 `window.__LATTE_SCENE__`로 실제 Three.js 장면을 검사할 수 있습니다. 자동 테스트는 컵의 부모가 앞발인지, 걷기/회전 중 월드 좌표와 앞발 상대 좌표가 올바른지, 두 독립 브라우저에서 원격 다리가 움직이고 마시는 컵이 기울어지는지를 확인합니다. 이 검사 접근점은 프로덕션에서는 제공하지 않습니다.

## 기존 Supabase 프로젝트 연결

`cafe_rooms`, `room_presence`를 생성·삭제·수정하지 않습니다. `cafe_rooms`는 `id` 정렬의 첫 10개 행에서 `name`을 읽습니다. 스키마나 SELECT 권한이 다르면 기본 방 이름을 사용합니다. 방 식별자는 기존 앱의 1~10 번호입니다.

Realtime의 public channel 연결을 허용해야 합니다. Postgres Changes 설정과 별개로 아바타는 Presence/Broadcast를 사용합니다.

- 브라우저당 Supabase 클라이언트 / WebSocket 하나. 평소 현재 방 + 전체 접속 현황 2채널, 방명록을 열었을 때 INSERT 구독 1채널을 추가합니다.
- Presence로 실제 입·퇴장과 방별 인원수를 계산합니다. 전체 현황에는 방 가입을 마친 이용자의 현재 방만 track합니다. `room_presence`의 행 수를 실제 동접으로 간주하지 않습니다.
- 위치·방향·좌석·컵/디저트 종류·양·테이블 배치·동작/시작 시각을 변경 시에만 **최대 5Hz**로 보냅니다. 입장 스냅샷에도 같은 제한을 적용하고 원격 위치·회전·손동작은 각 기기에서 보간/애니메이션합니다.
- 방울은 생성 목록과 pop ID만 전송합니다. seed/시각으로 궤적을 계산하며 고유 UUID·tombstone으로 중복/역순 이벤트를 처리합니다. 새 입장자는 기존 방울 스냅샷을 받습니다.
- 방 이동 시 구독과 방울을 정리하고 진행 중 섭취·추출을 취소합니다. SDK 자동 재접속, 재가입 시 Presence·방울 재동기화, 오류 상태 표시를 제공합니다. 오프라인 중 만든 방울은 재접속 후 재전송하지 않습니다.
- 기존 형태의 아바타 메시지도 수신합니다. 새 음료/동작을 표시하려면 배포 후 모든 브라우저를 새로고침하세요. v4 좌석은 위의 대표 승인/임대 방식으로 처리합니다.

## 영구 방명록 설정

왼쪽 벽 코르크 게시판 또는 `방명록` 버튼에서 엽니다. 모든 방이 같은 최신 50개 메모를 공유하고 새 INSERT를 Realtime으로 갱신합니다. 닉네임 1~16자, 메시지 1~100자, 기본 비속어·링크·반복 문자 검증을 적용하며 JSX 텍스트로만 렌더링합니다.

### Supabase에 적용

1. SQL Editor에서 [202611020001_guestbook.sql](supabase/migrations/202611020001_guestbook.sql)을 **한 번 실행**합니다. 또는 Supabase CLI로 해당 migration을 적용합니다. 이 파일은 새 `public.cafe_guestbook`, 비공개 `latte_private.guestbook_rate`, 저장 RPC와 읽기 정책을 생성합니다. 같은 SQL을 중복 실행하는 용도는 아닙니다.
2. Auth → Providers / Sign In 설정에서 **Anonymous Sign-ins**를 활성화합니다. 앱이 첫 작성 때 `signInAnonymously()`를 호출하며 로그인 화면은 없습니다. 세션은 Supabase SDK가 유지합니다.
3. 공개 운영 전 Auth의 익명 가입 rate limit을 확인하고 **CAPTCHA를 활성화하는 것을 권장합니다**. Cloudflare Turnstile 사이트를 만들어 실제 도메인과 개발 도메인을 등록합니다. Turnstile **secret은 Supabase Auth의 CAPTCHA 설정에만** 입력하고 공개 site key만 `VITE_TURNSTILE_SITE_KEY`에 입력합니다. Auth CAPTCHA를 켰다면 site key도 반드시 설정해야 새 익명 세션을 만들 수 있습니다. 기존 프로젝트의 다른 익명 인증 사용처에도 CAPTCHA 활성화가 영향을 줍니다.
4. migration이 `supabase_realtime` publication이 있으면 방명록 테이블을 추가합니다. 없다면 프로젝트의 Realtime 설정에서 `public.cafe_guestbook` INSERT를 publication에 추가하세요.
5. Supabase 연결 후 서로 다른 브라우저에서 작성·재접속·다른 방의 새 글 갱신을 확인하세요. 사람 확인 실패, 익명 인증 비활성화, 미적용 SQL/권한 오류는 화면에 안내합니다.

### 서버 측 남용 방지

- `anon`/`authenticated`는 공개 글 읽기만 가능하며 **테이블 INSERT/UPDATE/DELETE 권한이 없습니다**. 무제한 공개 쓰기 정책을 만들지 않습니다.
- 저장은 `authenticated` 역할의 제한된 `post_cafe_guestbook` RPC만 허용합니다. 익명 Auth 사용자도 이 역할을 받습니다. 클라이언트의 임의 visitor ID를 신뢰하지 않고 JWT의 `auth.uid()`를 사용합니다.
- `SECURITY DEFINER` + 빈 `search_path`, 비공개 rate log, 트랜잭션 advisory lock으로 검사와 쓰기를 묶습니다.
- 사용자당 60초 1회, 시간당 5회, 같은 메시지 하루 1회. **익명 계정을 바꿔도 전체 시간당 100회**의 서버 상한을 적용합니다. 이 상한은 프로젝트 규모에 맞춰 SQL에서 신중하게 조정하세요. IP 제한은 구현했다고 주장하지 않습니다.
- rate log는 24시간이 지나면 다음 RPC 호출 시 정리합니다. 공개 글에는 인증 UUID를 저장하지 않습니다. 글 삭제는 관리자 SQL/서버 권한으로 처리합니다.
- 기본 금칙어 검사는 완전한 콘텐츠 모더레이션이 아닙니다. Auth CAPTCHA·가입 제한·대시보드 모니터링과 관리자 삭제를 병행하세요. 더 큰 공개 서비스에서는 신뢰할 수 있는 Edge Function에서 검증한 IP/추가 제한과 신고·관리 화면을 확장할 수 있습니다.

Chromium이 `/usr/bin/chromium`에 있으면 사용하고 없으면 Playwright 설치본을 사용합니다. `CHROMIUM_PATH`로 경로를 지정할 수 있습니다.

브라우저 테스트는 바닥 탭 이동·장애물 우회·낮은 시점·독서·성장/개화 초기화·동시 물주기·좌석 승인·정원 복원에 더해 실제 WebGL과 PC/모바일 입력, 마우스 회전·휠·리셋, CDP 한 손가락/두 손가락 제스처, 이동 분리, 기존 좌석·방울, 추출·섭취·접시 정리, 음량 저장·오디오 초기화 방지를 확인합니다. 2개 브라우저가 실제 Supabase SDK와 **모의** Phoenix/PostgREST/Auth 서버를 사용해 Presence·Broadcast·섭취 동작·방 분리·재접속·공유 방명록을 검증합니다. SQL은 PGlite에서 실제 PostgreSQL 권한과 RPC 제한을 검사합니다. GitHub Actions에서 타입/빌드·로직·브라우저 검증을 실행합니다.

**로컬 테스트와 실제 서비스 검증은 별개입니다.** 실제 Supabase 자격 정보가 없는 환경에서는 hosted Auth/Realtime/SQL 적용, Turnstile 실서비스, 실물 모바일 성능, Vercel 배포가 확인되었다고 주장하지 않습니다. 실제 스피커에서의 ASMR 음질 청취도 자동 일정 검증과 별도로 확인해야 합니다. 전체 100명 동접은 목표이며 보장 수치가 아닙니다. DPR 최대 1.5, 저폴리곤 메시, 초기 프레임 접촉 그림자, 방울 50개/파티클 그룹 20개 제한을 적용하지만 100명 실부하 테스트는 별도로 필요합니다. Broadcast는 수신자 수만큼 메시지 비용이 늘어나므로 Supabase 무료 플랜의 최신 연결·메시지·처리량 한도를 확인하세요.

## Vercel 배포 및 실서비스 확인

GitHub main에 push해도 **Vercel 프로젝트 연결 여부를 확인하지 않았다면 자동 배포를 확정할 수 없습니다**. 연결된 Vercel Git 프로젝트에서 Production Branch가 `main`이고 자동 배포가 켜져 있으면 새 커밋이 배포됩니다.

1. 실제 서비스 주소: https://latte-room2.vercel.app/ . Vercel에서 기존 프로젝트의 Git 저장소 연결과 main Production Branch를 확인하세요.
2. Vite / Install `npm ci` / Build `npm run build` / Output `dist`.
3. Production/Preview의 Supabase 변수와 필요한 Turnstile site key 등록. 변경 후 Redeploy.
4. Deployments에서 해당 Git 커밋이 **Ready**인지 확인하고 배포 URL에서 새로고침. 개발자 도구에서 `document.querySelector('meta[name="application-version"]')?.content`가 `4`인지 확인할 수 있습니다. 1인칭/3인칭 전환, 책장, 화분과 바닥 클릭 산책이 표시되는지도 확인하세요.
5. PC + 모바일(서로 다른 브라우저)의 같은 방에서 인원·이동·컵·마시기/먹기·방울/pop을 서로 확인.
6. 마우스/터치 카메라 조작 중 캐릭터가 이동하거나 의자가 선택되지 않는지, 리셋/줌 한도와 음소거·볼륨 저장을 확인.
7. 다른 방에 있는 두 브라우저에서 방명록 작성 → 실시간 목록 갱신 → 새로고침 후 유지 확인. 1분 내 두 번째 작성이 서버에서 거부되는지도 확인.
8. 서로 다른 브라우저에서 같은 의자/화분을 동시에 골라 중복 착석/중복 성장이 없는지, 독서/물주기 모션이 보이는지, 개화 3분 후 다시 씨앗이 되는지 확인.
9. 네트워크를 끊고 복구해 정원 복원·재접속과 방 인원을 확인. Auth CAPTCHA가 켜졌다면 새 시크릿 브라우저에서 사람 확인도 테스트.

## 코드 위치

`world.ts`/`navigation.ts`는 배치·충돌·경로, `HealingObjects.tsx`는 독서와 정원 모델, `roomState.ts`/`useSharedRoom.ts`는 일시적 방 상태와 승인, `Scene.tsx`는 기존 월드/방울, `Avatar.tsx`와 `animation.ts`는 관절·걷기·앞발 컵, `brewing.ts`와 `brewAudio.ts`는 단계별 추출 일정/합성음, `nickname.ts`는 표시용 랜덤 이름, `CameraRig.tsx`/`camera.ts`는 눈 위치·낮은 추적 카메라와 입력 분리, `FirstPersonHands.tsx`는 로컬 소지품 표시, `CafeObjects.tsx`는 머신·컵·디저트·쇼케이스·게시판, `App.tsx`는 UI/동작 수명, `realtime.ts`는 기존 Supabase 연결, `audio.ts`는 자체 합성 음원과 설정, `Guestbook.tsx`와 SQL migration은 영구 방명록을 담당합니다.

### 추적 카메라 검증

`tests/browser/camera-follow.spec.ts`는 실제 Chromium WebGL에서 PC의 눈 위치 추적·바라보는 방향 이동·위/아래 둘러보기·바닥 자동 이동·컵 표시/마시기·3인칭 추적/줌/설정 복원과 모바일 CDP 드래그·조이스틱·핀치·바닥 탭을 검사합니다. 실제 모바일 기기 및 실제 Supabase/Vercel 운영 배포 확인은 이 자동화와 별개입니다. 이전 고정 상공 카메라 좌표를 가정하던 소품 테스트는 실제 추적 카메라를 드래그/줌하여 투영한 좌표를 사용하도록 변경했습니다.

카메라 수정 배포는 `document.querySelector('meta[name="camera-version"]')?.content`가 `2`인지와 첫 입장 시 캐릭터가 보이는 3인칭과 1인칭/3인칭 버튼을 확인하세요. 이 수정에는 추가 환경변수나 Supabase SQL이 없습니다.

`third-person-follow.spec.ts`는 PC/모바일에서 기본 3인칭, 과거 1인칭 설정 정리, 실제 이동량과 카메라 이동량, 캐릭터 화면 중앙 유지·배경 스크롤·정지·바닥 자동 이동·터치 회전/핀치를 검사합니다.

## 조용한 근접 안내와 독서

자동 상호작용 카드는 같은 오브젝트 근처에 연속 2초 머무른 뒤 하나만 표시합니다. 3초 뒤 닫히며, 같은 방의 같은 오브젝트는 표시 후 5분, 닫기 버튼으로 닫은 후 10분 동안 자동 재표시하지 않습니다. 다른 오브젝트가 가까워져도 표시 중인 카드를 바꾸지 않습니다. 시간 제한은 현재 앱 세션에서 방/종류/오브젝트별로 유지하며 새로고침하면 초기화됩니다. 직접 클릭/터치한 메뉴는 이 시간 제한을 적용하지 않습니다. 이동·자동 산책·카메라 드래그 중에는 자동 안내를 보류하고 멈춘 뒤 머무름 시간을 다시 셉니다. 자동 카드는 이동 입력이나 카메라를 잠그지 않으며, 실제 메뉴를 선택했을 때만 해당 상호작용을 수행합니다.

하단 `📖 책 읽기`는 근접 안내가 없어도 사용할 수 있습니다. 책장 전체와 확장된 책 표지를 클릭/터치해도 즉시 독서 메뉴가 열립니다. 여섯 표지에서 책을 선택하면 직접 쓴 짧은 문장을 읽고, `책 읽기 · 독서 의자로`로 가까운 빈 독서 의자까지 걸어가 앞발에 책을 펼칩니다. 앉아 있는 상태에서는 `책 읽기`/`책 덮기`로 전환하고 `일어나기`로 종료합니다. 페이지 애니메이션과 자체 합성 페이지 소리는 기존 효과음 설정을 따르며, 자동재생을 허용하지 않은 상태에서는 소리를 만들지 않습니다. 독서 상태/책 번호는 기존 5Hz 이내 Player Broadcast에 포함되어 다른 방문자도 앞발의 책과 독서 동작을 봅니다. 새 SQL이나 환경변수는 필요하지 않습니다.

`interactionHints.test.ts`는 머무름·3초 만료·5분/10분 재표시 제한·다른 카드로 교체하지 않기·방 분리를 시계 값으로 검증합니다. `reading-hints.spec.ts`는 모바일 하단 버튼, 실제 책장 터치, 책 선택·문구·착석·앞발 책·페이지 애니메이션과 자동 안내의 표시/만료를 검사합니다.
